
## 7. 软件和技术栈

这是目前缺失最明显的部分，需要补充：

- 使用什么开发语言
- 使用 vbot 的什么 SDK 或控制接口
- 使用什么视觉识别算法
- 使用什么人体姿势识别模型
- 使用什么语音识别方案
- 使用什么语音合成方案
- 是否使用大语言模型
- 机器狗如何接收控制指令
- 使用 Wi-Fi、蓝牙还是其他通信方式
- 是否有手机端、网页端或电脑端
- 姿势识别是在本地运行还是云端运行

主要使用 **Python 3.10**，基于 **ROS 2 Humble** 和 `rclpy` 开发；使用 Bash 脚本和 systemd 管理启动与开机自启。

使用 Vbot EDU 机身开放的 **ROS 2 topic/service 接口**，不是单独封装的手机 SDK。主要包括 `/perception/poses` 人体关键点、`/function_input` 动作 DAG、`/sm/action/lowlevel` 状态控制、`/head_action` 头部控制、`/get_jpeg_images` 拍照、显示和语音 PCM 接口。ROS 2 中间件使用 `rmw_zenoh_cpp`。

使用机器狗原厂提供的 **YOLO Pose 人体检测和关键点识别**。瑜伽垫实验模块还使用 OpenCV 的 HSV 颜色分割、轮廓提取和几何筛选，但目前人体动作触发主要依赖 YOLO Pose。

底层模型是机身上的 `yolo11`，输出 **17 个 COCO 人体关键点**。项目没有再部署 MediaPipe 等额外模型，而是在关键点上使用轻量规则判断下犬式、俯卧撑、静止和举手

使用 **Sherpa-ONNX 离线关键词识别**，直接处理机器狗麦克风的 PCM 音频流。用于识别“佳佳”“瑜伽功能”“俯卧撑”“下犬式”“拍照”“结束啦”等固定口令，不需要联网。

当前稳定方案不是实时 TTS，而是播放保存好的 **16 kHz、16-bit、单声道 WAV**。例如“瑜伽开始了”使用从机器狗内置 AI 自然语音中采集并处理的音频，通过 `/speech_phone_to_dog` 播放。结合原厂自定义文本 TTS 接口曾能接收请求。

项目的瑜伽模式、视觉识别、语音口令和动作控制 **不使用大语言模型**可以调用机器狗原厂的自由对话功能可能使用云端 AI Agent.

有两类输入：麦克风采集语音并进行离线关键词识别；摄像头通过 YOLO Pose 输出人体姿势。识别结果进入本机的状态机，再通过 ROS 2 服务调用动作 DAG、头部、屏幕、音频和相机接口。


功能程序直接运行在机器狗本机，Vbot 原厂手机 App 可以保留，但不是瑜伽功能的必要组成部分，开发网页接收机器狗拍摄的照片上传至云端。
**完全在机器狗本地运行**。YOLO Pose 推理、17 个关键点处理和动作规则判断均在机器狗内部完成，不需要将摄像头画面上传云端。

建议最终写成：

```text
硬件层：vbot AI机器狗、摄像头、麦克风、扬声器
感知层：人体姿势识别、瑜伽垫边界识别、语音识别
决策层：运动流程控制、异常判断、交互逻辑
执行层：机器狗移动、语音回复、动作反馈、拍照、握手
```

## 9. 功能的触发条件和反馈方式

现在的功能描述比较丰富，但需要进一步说明每个功能具体怎么发生。

| 功能 | 触发条件 | 机器狗动作 | 用户反馈 |
|---|---|---|---|
| 久坐提醒 | 用户久坐超过设定时间 | 语音或移动提醒 | 邀请用户起身拉伸 |
| 定时邀请 | 到达预设时间 | 主动发起瑜伽邀请 | 用户选择开始或拒绝 |
| 姿势识别 | 用户开始动作 | 分析人体关键点 | 语音提示动作状态 |
| 异常提醒 | 用户停留过久或状态异常 | 暂停、靠近或语音提醒 | 提示用户休息或调整 |
| 语音控制 | 用户发出指令 | 执行相应动作 | 语音或机械动作回应 |
| 安全避障 | 检测到人体或边界 | 调整移动路径 | 避免碰撞 |
| 运动结束 | 流程完成或用户指令触发 | 拍照、握手或鼓励 | 形成奖励反馈 |

---




| 功能 | 具体触发条件 | 机器狗反馈 | 用户反馈 |
|---|---|---|---|
| **唤醒佳佳** | 离线识别到“佳佳”，开启10秒指令窗口 | 眨眼并播放唤醒提示音 | 用户通过声音和眨眼确认唤醒成功，继续说“瑜伽功能”等指令 |
| **进入瑜伽模式** | 唤醒后10秒内说“瑜伽功能”或“瑜伽模式” | 先站立，再执行开心动作；播放“瑜伽开始了”；眨眼并闪屏 | 用户确认模式已经启动，可以开始做下犬式、俯卧撑或使用语音指令 |
| **随机看人** | 瑜伽模式开启且视觉检测到人体 | 每隔约4～7秒随机跟踪脸部或身体 | 用户可以从机器狗头部朝向判断自己是否进入取景范围，并适当调整位置 |
| **自动跟做下犬式** | 检测到倒V形人体姿态并连续稳定约1.2秒 | 执行一次下犬式，完成后恢复站立 | 用户看到机器狗模仿动作，确认姿势识别成功；离开姿势后可进行下一项动作 |
| **语音执行下犬式** | 瑜伽模式内说“下犬式” | 执行一次下犬式并回正 | 用户观察动作是否符合预期，动作结束后继续发出其他口令 |
| **自动跟做俯卧撑** | 检测到肩、髋和腿部近似水平并连续稳定约1.2秒 | 执行缩短版俯卧撑动作 | 用户看到机器狗跟做，确认俯卧撑被识别；结束当前姿势后可再次训练 |
| **语音执行俯卧撑** | 瑜伽模式内说“俯卧撑” | 执行俯卧撑动作 | 用户通过机器狗动作确认指令识别成功；5秒内不必重复口令 |
| **坐下看人** | 用户身体连续静止约5秒，或说“坐下看我”等口令 | 执行坐下/趴下看人动作 | 用户感受到机器狗的陪伴和关注；继续运动后，系统重新观察新的姿势 |
| **十秒倒计时** | 说“倒计时”“十秒倒计时”或“开始倒数” | 先坐下，播放十秒倒数，完成后恢复站立 | 用户根据声音保持当前姿势，并在倒数结束后放松或切换动作 |
| **拍照** | 瑜伽模式内说“拍照”，且机器狗处于静止状态 | 调用相机拍照，屏幕短暂闪烁，照片保存到本地 | 用户通过闪屏确认已经拍摄，可在电脑端查看或下载照片 |
| **绕人运动** | 说“绕圈”，目标、距离、障碍物和安全状态检查通过 | 根据用户朝向选择方向并绕行 | 用户保持相对静止并为机器狗留出安全空间，通过运动结果确认执行完成 |
| **结束并击掌** | 瑜伽模式内说“结束啦” | 当前任务完成后执行右侧击掌，并退出瑜伽模式 | 用户伸手配合击掌，通过击掌动作确认本次瑜伽互动结束 |
| **独立看人** | 说“看着我”或“盯着我” | 开启头部跟踪；收到停止口令后回正 | 用户移动身体测试跟踪效果；说“别看了”或“停止跟踪”结束功能 |

## 12. 安全说明

项目涉及机器狗移动、运动指导和用户身体状态识别，需要单独写安全边界。

建议说明：

- 伽伽狗提供的是轻量运动陪伴，不替代专业教练或医疗建议
- 用户可以随时通过语音指令停止机器狗
- 机器狗移动前需要确认周围空间
- 机器狗不会主动压迫或接触用户
- 检测到异常停留、跌倒风险或动作异常时进行提醒
- 避障功能仍属于原型阶段，需要在安全环境下体验
- 不保存或公开用户的人脸、语音和身体图像，或者说明数据保存方式
