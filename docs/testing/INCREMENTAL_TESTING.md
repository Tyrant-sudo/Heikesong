# 增量功能与回归规则

## 新增功能的固定流程

1. 在 `TRACEABILITY.md` 分配新的需求 ID；已发布 ID 永不改义或复用。
2. 在对应模块后增加接口或可选数据字段，避免感知算法直接依赖机器人 SDK。
3. 先补 L1/L2 测试和场景用例，再接入真实硬件。
4. 更新 `V1_TEST_LIST.md`、测试配置版本和 `CHANGELOG.md`。
5. 执行影响范围回归和 V1 核心冒烟，报告中记录 Git SHA。

## 影响范围回归

| 变更位置 | 必须回归 |
|---|---|
| 垫子识别 | `TC-MAT-001`、`TC-MAT-002`、`TC-BEH-001`、`TC-E2E-001` |
| 用户定位/方向 | `TC-PER-001`、`TC-BEH-002`、`TC-POSE-001`、`TC-E2E-001` |
| 姿态识别 | `TC-POSE-001`、`TC-ACT-001`、`TC-E2E-001` |
| 行为或机器人适配 | 对应行为用例、`TC-SAFE-001`、`TC-E2E-001` |
| 相机拍照 | `TC-ACT-001`、隐私检查、`TC-E2E-001` |
| 计时器 | `TC-TIM-001`、`TC-E2E-001` |
| 安全逻辑 | `TC-SAFE-001` 及所有会移动的场景 |

## 版本规则

- 补丁版本：不改变对外契约的修复或测试补充。
- 次版本：向后兼容的新能力、新事件或可选字段。
- 主版本：需要调用方同步修改的契约变化。
- 模型、阈值、固件、SDK 和测试数据集分别记录版本，不能只记录应用版本。

## 每次合并的最小完成定义

- 新需求有稳定 ID、验收标准和责任模块。
- 至少有一个正常路径、一个边界/失败路径测试。
- 所有移动行为有取消测试和 Safety Override 回归。
- 自动校验和受影响测试通过；受 SDK 阻塞的测试明确标为 `Blocked-by-SDK`。
- 测试表单包含代码、模型、配置、设备和证据引用。
