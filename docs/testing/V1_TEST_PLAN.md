# V1 测试计划

## 1. 目标与范围

V1 验证以下闭环：

```text
识别瑜伽垫 → 在垫边安全环绕 → 定位用户 → 跟随用户方向
→ 识别下犬式 → 机器狗模仿并拍照 → 计时完成
```

包含六项产品能力：瑜伽垫识别与边界定位、垫边环绕、用户位置识别、下犬式识别与模仿/拍照、用户方向跟随、计时。安全停止、障碍抢占、动作取消和事件追踪是这些能力的验收前提，不作为额外产品功能扩张。

V1 暂不验收多人目标选择、语音交互、其他瑜伽体式、录像、健康判断、自定义步态或未授权的设备接口。

## 2. 测试环境

| 环境 | 用途 | 硬件要求 |
|---|---|---|
| `SIM-MOCK` | 状态、计时、行为、去重和安全抢占 | 无真实机器狗 |
| `OFFLINE-CV` | 垫子、用户位置、方向和下犬式录像回放 | GPU 可选 |
| `HIL-SDK` | 厂商接口、运动、停止和拍照 | 正式开放 SDK 的设备 |
| `HIL-VBOT-EDU` | Vbot EDU 身份、接口、传感器、停止和 V1 冒烟 | Vbot 大头 EDU + 匹配的厂商开发包 |
| `FIELD-YOGA` | 封闭场地端到端验收 | 机器狗、瑜伽垫、软隔离、急停人员 |

目标真机已固定为 Vbot 大头 EDU。真机测试前按 `VBOT_EDU_TEST_PLAN.md` 记录序列号、硬件修订、固件、SDK、中间件、网络、允许速度/距离以及急停方式；未完成设备枚举时标记 `Blocked`，但 `SIM-MOCK` 与 `OFFLINE-CV` 正常推进。

## 3. 测试层级

| 层级 | 内容 | 主要证据 |
|---|---|---|
| L0 | 目录、需求 ID、用例 ID、配置和表单完整性 | 自动校验日志 |
| L1 | 纯逻辑、边界、计时、状态与事件去重 | 单元测试报告 |
| L2 | 感知结果→行为→Mock 设备，安全抢占 | 集成日志与调用时间线 |
| L3 | 正式 SDK 的运动、停止、拍照和反馈 | 设备/固件/SDK 记录 |
| L4 | 真实瑜伽场景的单项与端到端验收 | 测试表单与匿名化证据 |

## 4. 执行阶段

| 阶段 | 内容 | 完成标志 |
|---|---|---|
| T0 基线 | 架构、需求、用例、表单和 Mock 契约 | 结构校验及计时单测通过 |
| T1 数据校准 | 标注垫子、用户与姿态数据，冻结阈值 | 配置中的感知阈值不再为 `null` |
| T2 离线集成 | 环绕/跟随规划、触发去重、计时、安全抢占 | 单项场景在 Mock 中通过 |
| T3 真机接口 | Vbot EDU 身份、接口、停止、动作、拍照 | `TC-HW-EDU-001` 至 `008` 满足对应门禁 |
| T4 现场验收 | 六项功能完整闭环与安全回归 | 满足退出条件并形成报告 |

## 5. 进入条件

- 本轮需求与测试编号已进入追踪矩阵。
- Git SHA、应用、模型、配置、数据集、设备、固件和 SDK 均可追溯。
- 所有用于 Pass/Fail 的阈值已经冻结；`null` 阈值只允许探索性执行。
- 真机运动已完成 SDK 能力确认、场地隔离、急停演练和人员分工。
- 真人图像已授权，明确保存位置、访问权限和删除日期。

## 6. 退出条件

- 所有“必须”用例通过率 100%。
- 所有“高”优先级用例通过率至少 95%，其余失败项有书面处置决定。
- 不存在未关闭的 Blocker 或 Critical 缺陷。
- 环绕和跟随均通过 Safety Override，且不会同时获得运动控制权。
- 姿态会话只触发一次模仿和一次照片，事件、动作和照片关联 ID 一致。
- 主流程使用冻结配置连续完成 10 轮，无无限移动、重复触发或计时异常。
- 测试批次表、汇总表和隐私清理记录完整。

人身安全距离、速度、停止时间和硬件限制只能来自厂商资料和受控实测批准值，不由本计划预设。

## 7. 缺陷等级

| 等级 | 定义 | 示例 |
|---|---|---|
| Blocker | 可能造成人身/设备危险或无法停止 | 失联后继续移动 |
| Critical | V1 主链不可完成且无替代路径 | 垫子始终识别失败、动作无法取消 |
| Major | 核心结果明显错误 | 下犬式高误触发、重复拍照、计时漏算 |
| Minor | 不阻断核心体验 | 非关键日志字段缺失 |

## 8. 报告要求

每次执行使用 `forms/V1_TEST_RECORD.md` 或 CSV 表单，批次结束填写 `forms/V1_TEST_SUMMARY.md`。至少记录用例、轮次、Git SHA、模型/配置/设备版本、预期与实际结果、指标、证据引用和缺陷 ID。

## 9. 增量策略

后续能力按 `INCREMENTAL_TESTING.md` 新增需求 ID 和用例，不修改既有编号含义。每次变更执行受影响用例、下游动作、安全用例和 `TC-E2E-001`，避免仅测试新增功能。
