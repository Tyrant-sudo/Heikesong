# V1 测试计划

## 1. 目标

验证机器狗能够在瑜伽空间中完成以下闭环，同时保证安全事件能够抢占一切普通行为：

```text
发现人 → 选择目标 → 安全靠近 → 坐下陪伴
→ 识别简单状态或手势 → 执行互动
→ 用户移动后重新跟随 → 回到闲逛
```

V1 测试以 `function.md` 为需求来源，所有需求在 `TRACEABILITY.md` 中获得稳定编号。

## 2. 范围

### 包含

- 人体存在、位置、高低位、下犬式和伸手识别。
- 目标选择、靠近、陪伴、跟随、Play-bow、Paw、环绕和随机打扰。
- 距离过近、障碍、语音停止、姿态异常、动作超时、低电量和连接中断。
- 相机跟踪、静止录像和低速移动录像。
- 行为状态机、动作取消和 Safety Override。

### 暂不包含

- 医疗诊断或伤害类型判断。
- 关节力矩级控制和自定义步态算法。
- 多机器狗协同。
- 未获厂商授权的接口破解、逆向或安全机制绕过。
- 专业云台级视频稳定性。

## 3. 测试环境

| 环境 | 用途 | 硬件要求 |
|---|---|---|
| `SIM-MOCK` | 状态机、安全规则、动作取消 | 无真实机器狗 |
| `OFFLINE-CV` | 录像回放、姿态和手势识别 | GPU 可选 |
| `HIL-SDK` | 厂商接口、运动、传感器和心跳 | 正式开放 SDK 的设备 |
| `FIELD-YOGA` | 封闭场地端到端验收 | 机器狗、软垫、障碍物、急停人员 |

执行真机测试前，必须记录：设备型号、用户版或 EDU 版、固件版本、SDK/接口版本、网络拓扑和紧急停止方式。

## 4. 测试分层

### L0：仓库与配置冒烟

- 校验目录、计划、追踪矩阵和场景文件存在。
- 校验测试编号没有重复。
- 每次提交和 Pull Request 自动执行。

### L1：单元测试

- 感知结果的数据模型和阈值边界。
- 目标选择、冷却时间、超时和状态迁移。
- 安全规则优先级和动作取消逻辑。
- 不依赖摄像头、网络或真实机器人。

### L2：集成测试

- 感知事件写入世界状态。
- 世界状态触发行为决策。
- 行为命令进入 Mock Robot Adapter。
- Safety Supervisor 抢占正在执行的行为。
- 录像、日志与行为时间线保持一致。

### L3：硬件在环

- 读取相机、深度、雷达、IMU、电量和连接状态。
- 调用站立、坐下、趴卧、头部、移动及停止接口。
- 验证动作反馈、取消、超时和失联保护。
- 所有移动测试先空载、限速、牵引保护，再逐步扩大范围。

### L4：场景验收

- 使用瑜伽垫、真人和真实障碍物执行主流程。
- 按不同身高、服装、光照、人数和移动速度重复。
- 每轮保留结果摘要；含个人信息的原始视频不进入 Git。

## 5. V1 执行阶段

| 阶段 | 工作内容 | 完成标志 |
|---|---|---|
| T0 基线 | 目录、编号、计划、Mock 接口 | 结构校验通过 |
| T1 离线感知 | 人体、姿态、手势录像回放 | 高优先级感知用例通过 |
| T2 行为集成 | FSM、目标选择、动作取消 | 主链在 Mock 环境连续通过 |
| T3 真机接口 | SDK、传感器、动作、心跳 | 所有必须接口完成安全验证 |
| T4 现场验收 | 主流程、摄像和安全回归 | 满足 V1 退出条件 |

T3 依赖厂商正式开放控制接口。如果只有普通用户版且不支持二次开发，T0–T2 正常推进，T3–T4 标记为 `BLOCKED-BY-SDK`，不得用非授权方式解锁。

## 7. 进入条件

- 需求编号和对应验收标准已确认。
- 测试环境配置有版本记录。
- Mock 接口或厂商 SDK 的能力边界已列出。
- 真机测试已完成场地检查、急停演练和操作员分工。
- 涉及真人数据时已取得授权并确定删除周期。

## 8. 退出条件

- 所有“必须”需求测试通过率为 100%。
- 所有“高”优先级需求通过率不低于 95%，未通过项有明确处置决定。
- 不存在未关闭的阻断级或严重级安全缺陷。
- Safety Override 在每一种普通运动行为中都成功完成抢占。
- 主流程在目标场地连续完成至少 10 轮，无无限跟踪、无限动作或失控移动。
- 连接中断、低电量、动作超时和操作员停止均进入厂家规定的安全状态。
- 生成测试报告，记录固件、模型、配置和代码提交 SHA。

以上数字是 V1 项目发布门槛；人身安全距离、最大速度、停止时间等参数必须以厂商安全资料和实测批准值为准。

## 9. 缺陷等级

| 等级 | 定义 | 示例 |
|---|---|---|
| Blocker | 可能造成人身或设备危险，或无法停止 | 安全指令无效、失联继续移动 |
| Critical | 主链完全失败且无可接受替代 | 无法检测人员、无法取消动作 |
| Major | 核心体验明显错误 | 频繁选错目标、下犬式高误触发 |
| Minor | 不阻断核心体验 | 日志字段缺失、轻微构图偏移 |

## 10. 测试证据

每次测试至少记录：

- 测试编号和执行时间。
- Git commit SHA。
- 模型、配置、固件和 SDK 版本。
- 环境、人员数量、光照和障碍物布置。
- 预期结果、实际结果和通过状态。
- 缺陷编号及可复现步骤。

## 11. 主要风险

- 普通用户版没有正式 SDK，导致真机阶段阻塞。
- 人体遮挡、宽松服装和瑜伽动作造成姿态误判。
- 感知延迟与运动命令叠加，导致停止不及时。
- 多人场景目标 ID 切换，导致跟错人。
- 真实视频涉及隐私，不能直接进入代码仓库。
