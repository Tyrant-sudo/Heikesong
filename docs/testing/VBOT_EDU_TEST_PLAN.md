# Vbot EDU 硬件测试版本 0.1.0

## 1. 目标

确认交付设备确实为 Vbot 大头 EDU，并冻结与 V1 六项能力有关的系统、感知、运动、相机、网络和安全属性。该版本只验证正式开放接口，不进行逆向、破解、越权访问或底层步态改写。

## 2. 硬件测试列表

| 编号 | 属性域 | 核心检查点 | 进入运动测试前 |
|---|---|---|---|
| `TC-HW-EDU-001` | 身份与版本 | 型号、EDU 标识、序列号、固件、镜像、SDK、开发文档 | 必须通过 |
| `TC-HW-EDU-002` | 开发接口 | 厂商包完整性、ROS/中间件发现、node/topic/service/action/QoS/坐标系清单 | 必须通过 |
| `TC-HW-EDU-003` | 感知传感器 | RGB、深度、16 线雷达、时间戳、频率、丢帧和坐标变换 | 必须通过相关项 |
| `TC-HW-EDU-004` | 运动与停止 | 控制权、限速运动、零速、取消、急停、超时和停止反馈 | 必须通过 |
| `TC-HW-EDU-005` | 拍照链路 | 单帧抓取、关联 ID、文件引用、失败处理和隐私 | 拍照功能前必须通过 |
| `TC-HW-EDU-006` | 网络与恢复 | 连接、心跳、断网停止、重连不续跑、时间同步 | 必须通过 |
| `TC-HW-EDU-007` | 外设与电源 | 端口枚举、厂商规格核对、未接负载检查、扩展权限 | 按需通过 |
| `TC-HW-EDU-008` | V1 HIL 冒烟 | 垫子/用户/姿态输入、环绕/跟随限速命令、模仿、拍照和计时 | 单项门禁后执行 |

## 3. 执行顺序

```text
001 身份版本
  └─► 002 接口枚举
       ├─► 003 感知流 ──► 005 拍照
       ├─► 006 网络/失联
       └─► 004 停止优先、再做运动
                    └─► 008 V1 HIL 冒烟
007 外设仅在需要扩展硬件时执行
```

## 4. 进入条件

- `config/device/vbot_edu.yaml` 已复制为本批次配置并填入可获得的实际值。
- 已取得厂商开发包、接入指南、许可证和与当前固件匹配的版本说明。
- 使用隔离场地、支撑/牵引保护、操作员和独立安全观察员。
- 运动速度、距离、动作范围和停止时间阈值已得到厂商资料或项目批准。
- 首次运动前已验证物理急停方式，电池和场地状态正常。

## 5. 退出条件

- `001`、`002`、`004`、`006` 全部通过，且无 Blocker/Critical 缺陷。
- V1 使用的相机、雷达、动作和拍照接口均已记录精确名称、类型、QoS、单位和坐标系。
- 断网、节点退出、动作超时和操作员停止均能进入厂商定义的安全状态。
- `008` 在限制速度下完成一次，随后才能进入 `FIELD-YOGA` 多轮验收。
- 测试记录包含 Git SHA、设备序列号、固件、SDK、配置和证据引用。

## 6. 结果状态

- `Pass`：观察结果达到已冻结标准。
- `Fail`：接口存在但结果不符合标准。
- `Blocked`：缺少厂商包、权限、批准阈值或必要配件。
- `Not Supported`：厂商明确说明当前设备/版本不提供；必须触发架构替代方案评审。
