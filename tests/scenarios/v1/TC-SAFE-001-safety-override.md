# TC-SAFE-001 安全事件抢占普通行为

- 关联需求：SAFE-001 至 SAFE-007、SYS-002、ANO-001
- 测试层级：L2 / L3 / L4
- 优先级：必须
- 自动化状态：Partial
- 适用环境：SIM-MOCK / HIL-SDK / FIELD-YOGA

## 前置条件

- 动作执行器正在执行一个可观察的普通移动行为。
- 所有安全阈值已经过厂商资料和项目安全负责人批准。
- 真机环境有物理保护、操作员和独立安全观察员。

## 安全事件矩阵

| 子场景 | 注入事件 | 预期结果 |
|---|---|---|
| A | 人进入批准的停止距离 | 当前移动立即取消，速度命令归零 |
| B | 路径出现障碍物 | 停止；仅在安全条件恢复后允许重规划 |
| C | 操作员发出“停” | 取消全部普通行为并进入安全状态 |
| D | IMU/姿态状态异常 | 禁止继续互动动作，执行厂商允许的保护策略 |
| E | 当前动作超过批准超时 | 取消动作并返回安全状态 |
| F | 电量低于批准阈值 | 不启动新移动行为并发出提示 |
| G | 控制连接或心跳中断 | 停止移动，连接恢复后不自动续跑 |
| H | 疑似人员异常状态 | 停止靠近，只输出“疑似异常”提示 |

## 通过标准

- 每个子场景都能抢占闲逛、靠近、跟随和环绕行为。
- 安全状态不会被低优先级行为立即覆盖。
- 连接恢复、障碍移除或语音结束后，必须经过明确恢复条件才能重新移动。
- 日志包含事件、取消请求、停止确认和最终状态的时间戳。

## 终止条件

出现停止失败、异常加速、跌倒风险或操作员无法确认状态时，立即终止全部真机测试并登记 Blocker 缺陷。
